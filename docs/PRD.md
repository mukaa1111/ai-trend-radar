# AI HRD 트렌드 레이더 (PRD)

작성일: 2026-10-16 · 상태: 기획 확정, 구현 전

## 한 줄 소개
생성형 AI 기술 변화와 AI/AX 시대의 일·학습·변화관리 흐름 중에서 "AI HRD 담당자이자 변화관리자가 오늘 읽을 만한 글 5개"를
자동으로 골라 요약해, 매일 아침 7시 텔레그램으로 보내주는 개인용 서비스.

## 누가 쓰나
- 나 한 사람. SK mySUNI에서 AI HRD 프로그램을 설계·운영하고, 조직의 AI 변화관리를 맡고 있다.
- 지금 관심사: ① **work redesign** (방법론·사례·프레임워크), ② **새 모델·서비스 출시에 따라 내가 새로 시도해 볼 것**,
  ③ AI/AX 시대의 성인학습·변화관리 흐름 (연구·조사 보고서·현장 사례).
- 한국어·영어 가리지 않는다. 영어 원문이면 요약은 한국어로, 난이도와 분량을 함께 표시한다.
- 폰 텔레그램으로 5분 안에 읽고, 더 볼 것만 원문 링크로 들어간다.

## 핵심 기능 (6개)
1. **매일 아침 7시 텔레그램 브리프** — 주말 포함 매일 07:00(한국)에 한 통. 글 5개 안팎, 각 글마다
   제목 / 출처 · 언어 · 분량 / 3줄 요약 / "HRD·변화관리자에게 왜 중요한지" 한 줄 / 원문 링크.
   맨 아래에 두 코너를 붙인다: **"오늘 해볼 것 1개"**(새 모델·기능이 나왔을 때 직접 시도해 볼 실험)와
   **"요즘 기술 화제 1건"**(AI 때문에 가능해진 기술 현상 한 가지. 예: 리버스 엔지니어링이 쉬워져 인디게임 카피본이 바로 뜨거나, 개인이 윈도 오류 패치를 만들거나,
   게임 시스템을 뜯어 숨은 정보를 공개하는 일. 무슨 일인지 3줄 + "일·학습·조직에 무엇을 뜻하나" 한 줄. 친구에게 설명할 수 있을 만큼 쉽게)
2. **출처 목록 + 보완 검색** — `docs/SOURCES.md`에 적힌 고정 출처(AI 기술 / AI×일·학습 / HRD·조직 / 국내 / 기술 화제)를 매일 돌고,
   관심사 키워드로 웹 검색을 보태 출처 밖의 좋은 글도 잡는다. 출처는 파일 한 줄 추가·삭제로 바꾼다.
3. **관심사 기준으로 고르기** — `docs/INTERESTS.md`의 관심사 순서(work redesign → 새로 시도할 것 → 성인학습·변화관리 → 기술 화제)로
   우선순위를 매기고, 제휴 발표·임원 인사·홍보성 사례·같은 내용 반복은 뺀다. 억지로 5개를 채우지 않는다(3개여도 됨).
4. **보관함 (데이터가 쌓이는 곳)** — 텔레그램은 "알림"일 뿐이고, 진짜 기록은 파일로 남는다.
   매일 브리프를 `briefs/2026-10-20.md`처럼 GitHub 저장소에 저장하고, 구글 드라이브 `AI Trend Radar/261016_new` 폴더에도 같은 파일이 쌓인다.
   글 하나하나는 `data/items.json`에도 (날짜, 제목, 출처, 태그, 요약, 링크) 형태로 쌓여 아래 웹페이지와 검색의 재료가 된다.
5. **지난 브리프 찾아보는 웹페이지** — "주말 뭐하지?"처럼 GitHub Pages로 여는 페이지 한 장. 날짜별 브리프 목록,
   검색창(제목·요약·출처), 태그 필터(work redesign / 해볼 것 / 성인학습·변화관리 / 기술 화제). 폰에서 열어 "지난달 work redesign 글"을 바로 찾는다.
   로그인 없음, 주소를 아는 사람만 본다. 텔레그램 브리프 맨 아래에 이 페이지 링크를 붙인다.
6. **중복 방지** — 최근 30일 동안 보낸 글 링크를 `data/items.json`으로 확인해 같은 글을 두 번 보내지 않는다.

## 어떻게 돌아가나 (가장 단순한 방식)
- **Claude 클라우드 루틴**이 매일 07:00에 깨어나 출처를 읽고, 브리프 파일을 GitHub 저장소(`mukaa1111/ai-trend-radar`)에 올리고, 텔레그램 봇으로 보낸다.
  → 이유: "주말 뭐하지?"에서 이미 검증된 방식이라 새로 배울 게 없고, PC가 꺼져 있어도 돌아간다.
- **텔레그램 봇** → 이유: 봇 하나 만들면 끝. 무료이고 설정이 메일·카카오보다 훨씬 쉽다.
- **GitHub 저장소**가 중간 창고, 드라이브 폴더는 그 복사본 → 이유: 클라우드는 PC의 H: 드라이브에 직접 쓸 수 없다.
- 팀 계정이 끝나면 루틴만 개인 Pro 계정에서 다시 만든다(절차는 `docs/ROUTINE.md`에 적어 둘 것). 저장소·텔레그램·드라이브는 모두 개인 계정이라 그대로.

## 이번엔 안 할 것
- 앱(설치형) 화면, 로그인·개인화 기능 (웹페이지 한 장으로 충분)
- 카카오톡·이메일 발송, 다른 사람에게 공유
- 원문 전체 번역, 한 글을 길게 정리한 심층 리포트
- 주간·월간 리포트 자동 생성 (2주 써 본 뒤 결정)
- 텔레그램에서 👍👎 눌러 취향 학습하기 (나중에)
- 유료 매체(HBR, MIT SMR 등)에 **대신 로그인해서 본문 읽어오기** — 자동 수집은 공개 요약까지만 하고 "유료" 표시를 붙인다.
  HBR 구독은 없다(2026-10-19 확정). 그래서 유료 글이 걸리면 ① 공개 요약·제목만 전하고, ② **같은 저자가 무료로 올린 글·팟캐스트·논문·인터뷰**를 찾아
  대신 링크한다(HBR 글은 대개 저자 블로그, LinkedIn, 대학 워킹페이퍼, HBR IdeaCast에 같은 내용이 공개돼 있다).
  유료 벽을 우회해 본문을 긁어 오는 방법(보관 사이트, 캐시 등)은 쓰지 않는다. HBR 무료 회원 한도(월 몇 편)는 내가 직접 쓴다.
