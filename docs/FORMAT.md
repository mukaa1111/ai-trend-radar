# 브리프 양식 (FORMAT)

매일 만드는 브리프 한 편의 모양이에요. 텔레그램 한 통(길면 두 통)과 `briefs/YYYY-MM-DD.md` 파일이 같은 내용을 담습니다.

## 머리
```
📡 AI HRD 레이더 · 10/19(월)
오늘 n건 · work redesign n · 해볼 것 n · 학습·변화관리 n
```

## 글 하나 (3~5개)
```
1. 제목 (한국어로 풀어 쓴 제목, 원제는 괄호)
   출처 · 언어 · 약 n분 · [유료] · [이해관계: ...]   ← 해당될 때만
   • 요약 1
   • 요약 2
   • 요약 3
   → 왜 중요한가: 한 줄 (HRD·변화관리자 관점)
   🔗 링크
```
- 태그는 셋 중 하나: `#work_redesign` `#해볼것` `#학습변화관리`
- 요약은 사실만. 평가·추측은 "→ 왜 중요한가" 줄에만.
- 영어 글은 난이도(상·중·하)를 분량 옆에 적는다.

## 꼬리 (두 코너 + 선택 한 줄)
```
📎 더 보기 한 줄 (선택) — 5개에 못 들었지만 알아 둘 글 1개, 걸러 읽을 이유 포함
🧪 오늘 해볼 것
   한 문장 실험 제안 + 어떤 글에서 나온 것인지
🔥 요즘 기술 화제
   제목 · 출처 · 링크
   • 무슨 일인지 3줄 (비개발자용)
   → 일·학습·조직에 뜻하는 것: 한 줄
📂 지난 브리프: https://mukaa1111.github.io/ai-trend-radar/  (Pages를 켠 뒤부터 붙인다)
```

## 파일
- `briefs/YYYY-MM-DD.md` — 위 내용 그대로 (맨 위에 `# 2026-10-19 브리프` 제목, 맨 아래 "못 연 출처" 한 줄)
- `data/items.json` — 글 단위 기록. 한 글 = `{ "date", "title", "source", "url", "lang", "tags": [], "summary": [3줄], "why", "paid": false, "coi": "" }`
  기술 화제 코너는 `tags: ["기술화제"]`, 해볼 것은 글이 아니라 `briefs/` 파일에만 둔다.
- 같은 `url`이 최근 30일 items.json에 있으면 다시 보내지 않는다.

## 길이
- 텔레그램 한 통은 4,000자 안쪽. 넘으면 "글 1~3 / 글 4~5 + 꼬리" 두 통으로 나눈다.
- 글 5개 기준 전체 1,800~2,500자 목표. 억지로 5개를 채우지 않는다.
