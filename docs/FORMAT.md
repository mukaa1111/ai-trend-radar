# 브리프 양식 (FORMAT)

매일 만드는 브리프 한 편의 모양이에요. 텔레그램 한 통(길면 두 통)과 `briefs/YYYY-MM-DD.md` 파일이 같은 내용을 담습니다.

## 머리
```
📡 AI HRD 레이더 · 10/29(목)
오늘 4건 · AI 트렌드 2 · 학습·변화관리 1 · 탐색: 스킬 기반 조직
```

## 글 하나 (3~4개) — 짧게!
```
1. 제목 (한국어, 40자 안쪽. 영어 원제는 쓰지 않는다)
   출처 · 언어(난이도) · 약 n분 · [유료] · 이해관계: … · 탐색: 영역    ← 해당되는 것만, 한 줄
   • 요약 1 (70자 안쪽)
   • 요약 2 (70자 안쪽)
   → 왜 중요한가: 한 줄 (60자 안쪽, HRD·변화관리자 관점)
   👀 반응: 한 줄 (70자 안쪽, 출처 표기. AI 트렌드 글만. 없으면 생략)
   🔗 링크
```
- 태그는 하나: `#AI트렌드` `#학습변화관리` `#탐색주제` (`#해볼것`은 직접 시도 제안이 핵심인 AI 트렌드 글에만)
- 요약은 사실만. 평가·추측은 "→" 줄에만, 남의 의견은 "👀" 줄에만.
- 수치는 원문에 있는 것만. 한 글에 숫자 2~3개면 충분.

## 꼬리 (두 코너)
```
🧪 오늘 해볼 것
   한 줄 (80자 안쪽) — 오늘 글 중 하나에서 나온 30분짜리 실험
🔥 요즘 기술 화제
   제목 · 출처 · 링크
   • 무슨 일인지 한 줄 (80자 안쪽, 비개발자용)
   → 일·학습·조직에 뜻하는 것: 한 줄 (60자 안쪽)
📂 지난 브리프: https://mukaa1111.github.io/ai-trend-radar/
```
"📎 더 보기"는 쓰지 않는다 (길어지는 주범). 꼭 알릴 글이 있으면 다음 날 본문에 넣는다.

## 파일
- `briefs/YYYY-MM-DD.md` — 위 내용 그대로 (맨 위에 `# 2026-10-19 브리프` 제목, 맨 아래 "못 연 출처" 한 줄)
- `data/items.json` — 글 단위 기록. 한 글 = `{ "date", "title", "source", "url", "lang", "tags": [], "summary": [2줄], "why", "reaction": "", "area": "", "paid": false, "coi": "" }` (reaction은 👀 줄, area는 탐색 주제 글의 영역 이름. 없으면 빈 문자열)
  기술 화제 코너는 `tags: ["기술화제"]`, 해볼 것은 글이 아니라 `briefs/` 파일에만 둔다.
- 같은 `url`이 최근 30일 items.json에 있으면 다시 보내지 않는다.

## 텔레그램에서 보이는 모양 (스크립트가 자동으로 꾸밈)
`scripts/send_brief.py`가 위 양식의 파일을 읽어 텔레그램용으로 바꿔 보낸다. 브리프 파일 자체는 그대로 두면 된다.
- 제목 줄 → 태그 색 이모지(🟡 AI 트렌드 · 🟢 해볼 것 · 🔵 학습·변화관리 · 🟤 탐색 주제 · 🟠 work redesign(옛 태그) · 🟣 기술 화제) + **굵게**. 영어 원제 줄은 뺀다.
- 출처 줄 → *기울임*, `#태그`는 지우고 맨 앞에 태그 이름을 붙인다.
- "→ 왜 중요한가:" → 💡 로 시작
- "🔗 주소" → "원문 보기 →" 글자에 링크를 숨긴다. 본문 속 다른 주소는 "링크"로 숨긴다.
- "---" 아래(못 연 출처)는 보내지 않는다.
- 확인: `python scripts/send_brief.py briefs/YYYY-MM-DD.md --dry-run` 으로 보내기 전에 미리 볼 수 있다.

## 길이
- **텔레그램에서 읽히는 글자 수 2,300자 안쪽** (한 통). `python scripts/check_brief.py` 가 텔레그램 기준 길이를 알려 준다. 2,300자 넘으면 경고, 3,000자 넘으면 실패.
- 파일 자체(`briefs/*.md`)는 링크·"못 연 출처"가 있어 조금 더 길다. 4,000자 안쪽.
