# 브리프 양식 (FORMAT)

매일 만드는 브리프 한 편의 모양이에요. 텔레그램 한 통(길면 두 통)과 `briefs/YYYY-MM-DD.md` 파일이 같은 내용을 담습니다.

## 머리
```
📡 AI HRD 레이더 · 10/19(월)
오늘 n건 · AI 트렌드 n · 학습·변화관리 n · 검토 주제 n
```

## 글 하나 (3~5개)
```
1. 제목 (한국어로 풀어 쓴 제목, 원제는 괄호)
   출처 · 언어 · 약 n분 · [유료] · [이해관계: ...]   ← 해당될 때만
   • 요약 1
   • 요약 2
   • 요약 3
   → 왜 중요한가: 한 줄 (HRD·변화관리자 관점)
   👀 반응: 얼리어답터·커뮤니티가 뭐라 하는지 1~2문장 (출처 표기. AI 트렌드 글에 가능하면 붙이고, 없으면 생략)
   🔗 링크
```
- 태그는 하나: `#AI트렌드`(새 모델·서비스·도구) `#해볼것`(직접 시도 제안이 핵심인 글) `#학습변화관리` `#work_redesign`(검토 주제) 
- 요약은 사실만. 평가·추측은 "→ 왜 중요한가" 줄에만.
- 영어 글은 난이도(상·중·하)를 분량 옆에 적는다.

## 꼬리 (두 코너 + 선택 한 줄)
```
📎 더 보기 한 줄 (선택) — 5개에 못 들었지만 알아 둘 글 1개, 걸러 읽을 이유 포함
🧪 오늘 해볼 것
   한 문장 실험 제안 + 어떤 글에서 나온 것인지
🔥 요즘 기술 화제
   제목 · 출처 · 링크
   • 무슨 일인지 3줄 (비개발자용)
   → 일·학습·조직에 뜻하는 것: 한 줄
📂 지난 브리프: https://mukaa1111.github.io/ai-trend-radar/  (Pages를 켠 뒤부터 붙인다)
```

## 파일
- `briefs/YYYY-MM-DD.md` — 위 내용 그대로 (맨 위에 `# 2026-10-19 브리프` 제목, 맨 아래 "못 연 출처" 한 줄)
- `data/items.json` — 글 단위 기록. 한 글 = `{ "date", "title", "source", "url", "lang", "tags": [], "summary": [3줄], "why", "reaction": "", "paid": false, "coi": "" }` (reaction은 👀 반응 줄, 없으면 빈 문자열)
  기술 화제 코너는 `tags: ["기술화제"]`, 해볼 것은 글이 아니라 `briefs/` 파일에만 둔다.
- 같은 `url`이 최근 30일 items.json에 있으면 다시 보내지 않는다.

## 텔레그램에서 보이는 모양 (스크립트가 자동으로 꾸밈)
`scripts/send_brief.py`가 위 양식의 파일을 읽어 텔레그램용으로 바꿔 보낸다. 브리프 파일 자체는 그대로 두면 된다.
- 제목 줄 → 태그 색 이모지(🟡 AI 트렌드 · 🟢 해볼 것 · 🔵 학습·변화관리 · 🟠 work redesign · 🟣 기술 화제) + **굵게**. 영어 원제 줄은 뺀다.
- 출처 줄 → *기울임*, `#태그`는 지우고 맨 앞에 태그 이름을 붙인다.
- "→ 왜 중요한가:" → 💡 로 시작
- "🔗 주소" → "원문 보기 →" 글자에 링크를 숨긴다. 본문 속 다른 주소는 "링크"로 숨긴다.
- "---" 아래(못 연 출처)는 보내지 않는다.
- 확인: `python scripts/send_brief.py briefs/YYYY-MM-DD.md --dry-run` 으로 보내기 전에 미리 볼 수 있다.

## 길이
- 텔레그램 한 통은 4,000자 안쪽. 넘으면 "글 1~3 / 글 4~5 + 꼬리" 두 통으로 나눈다.
- 글 5개 기준 전체 1,800~2,500자 목표. 억지로 5개를 채우지 않는다.
